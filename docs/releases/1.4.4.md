# 1.4.4 — 书架并发保存修复

修复后台书架刷新结束后，用旧列表覆盖新加入书籍的问题。刷新现在仅将成功抓取的元数据合并到最新书架，保留期间的新增、删除、换源、阅读进度、分组和自定义封面。

- 同一用户的书架读写共用互斥锁，网络抓取在锁外进行；保持现有 JSON 存储格式。
- 进度、分组、封面使用更新接口，不再用旧快照重写整本书，也不会重新添加已删除的书。
- 换源提交时按最新进度重新对齐章节。
- 书架通过同目录临时文件原子替换，临时文件权限为 0600，并记录提交操作、数量和增删书籍的 URL 哈希。
- 新进度使用毫秒时间戳，比较时兼容旧的秒时间戳。
- 前端拒绝过期书架响应；期间发生修改时重新读取当前书架。更新 PWA 页面缓存版本。
- 备份恢复仍使用显式全量替换；自动刷新不再调用该接口。

回归覆盖：刷新期间新增、删除、换源及字段修改；并发新增和分组修改；删除后延迟更新；并发读取时 JSON 完整；秒/毫秒进度比较；前端响应乱序和退出登录取消。

部署应先运行 Rust/前端测试，备份存储目录并保留旧镜像，再更新 reader-core 和 yomu-app。不要让多个 reader-core 进程共享同一书架目录；本次锁针对单实例部署。
